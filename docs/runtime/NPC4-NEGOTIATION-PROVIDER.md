# NPC4：修理换借用与可替换对话接口

2026-10-24（Asia/Shanghai）。分支 `codex/npc-negotiation-provider-20261023`，基于 NPC3 `c1790e55a4b5730dacf2d41b9616de9286bf2cad` / PR #11。限定功能候选；主线/Projects 仍待控制树复核。本轮未合 main、部署、调用真实模型或迁移存档。

## 玩家可以做什么

运行 `Start-NPC-Negotiation.cmd`，等待 ready，打开 `http://127.0.0.1:18348/demo-runtime.html`。使用 Node 24；Windows 启动器及真实浏览器外观尚未验。独立新档 `artifacts/npc4-negotiation/world`，不读旧社交档；输入 `quit` 并等 stopped 后正常重开。

点击附近的猎人，选择愿修理 20/40 点、想借 6/12/24 小时，提出条件。初始工具耐久 60、信任尚浅，猎人会要求实际修理 40 点，最多借 12 小时。玩家明确接受后点击“帮助修理”两次，再点击“按约领取工具”，最后按期“归还工具”。借用期限从实际领取开始；归还动作耗 10 分钟，须在截止时间前完成。

条款并非输入什么就答应什么。工具状况影响所需修理量，关系影响可借期限；害怕或积怨较重时可以拒绝。接受前一天内提议有效；接受后一天内须完成修理并领取。一时说“我修好了”不会增加耐久或履约进度。实际工具唯一，所有权仍属于猎人。重复领取、错误协议 ID、工具被拿走、又损坏、距离变化或当事人死亡都会阻止领取。伤害记录不会因帮助而消失；逾期只按原规则处罚一次，晚归还仍保留逾期记录。

猎人没看到偷窃时不会立刻知道工具离手，也不会凭空认识小偷。发现失物后才停止相应约定。沿用既有逐刻观察顺序：日结死亡当刻即禁止交互，关闭约定的记录在下一次时间步观察时补入。

## 对话接口如何使用

默认没有连接模型：手工协商、原九种互动与有限句式文字入口都能使用。自然对话区会明确显示未启用。它目前是接入完成、真实模型效果待验的候选，不能把离线受控回复称为自由对话能力通过。

在本项目 `.env` 填写独立的 `NPC_LLM_*` 配置；示例见根目录 `.env.example`。不继承旧 `LLM_*` 或其他项目凭据，不把密钥放在浏览器、仓库或聊天文本中。启动器显式加载本项目 `.env`；已有独立测试档须正常关闭后再重开才能更新进程配置。

```dotenv
NPC_LLM_ENABLED=true
NPC_LLM_BASE_URL=https://your-provider.example/v1
NPC_LLM_MODEL=your-tested-model
NPC_LLM_API_KEY=your-local-secret
```

上面是占位配置，不能直接调用。BASE_URL 不含 `/chat/completions`；适配器在末尾添加它。只接受 HTTPS，另允许本机 HTTP 受控测试。服务商须支持 `messages`、`response_format: {"type":"json_object"}`、`stream:false`、`max_tokens`，以及 `choices[0].message.content` / `finish_reason:"stop"`。这是一种明确的兼容协议，不能保证每个供应商都能直接使用。JSON 模式要求参考 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/json_mode/)；实现不绑定该服务商或模型。

每次明确点击“生成对话预览”才请求服务，可能产生费用；无后台轮询、自动重试或自动执行。默认每进程最多 32 个不同请求，同时 1 个；超时 20 秒，输入上下文 32 KiB、响应 64 KiB、模型内容 JSON 8 KiB，最多输出 900 tokens。预算按请求数计，不是金额上限，重开会重置，真实成本/速度尚未测量。同 ID/同内容的明确重试复用进程内结果，失败也占预算；不同内容复用 ID 被拒绝。

交互顺序：

1. 输入一段 240 个 UTF-16 码元以内、无换行的文字，生成预览。此时没有保存交谈或行动。
2. 检查预览，点击“确认交谈并保存”。保存的是“玩家说了什么、猎人回复了什么”，不证明话里的事情发生过。
3. 有行动建议时，再明确点击“确认建议”。协商建议先提交给世界得到正式条款，仍须另点接受；修理、借还、威胁等也必须过原动作规则。

页面切换人物、世界或修订后，晚到草稿不能提交。已有请求结果不确定时保留原 DTO，先确认/重试同一请求；不能用一段新话覆盖它。服务重启后的旧未提交签名失效，应重新生成；已落盘对话用原 DTO 重试则返回原回执，不再调用模型。

## 实现边界与后续

- fixture4 / map4 / mapViewVersion3，沿用 DTO5 / format11。旧 fixture1/2/3 不升级；新命令不对旧世界开放。
- 模型只读服务端构造的猎人私有视角：固定人物设定、本人身体/口粮/关系状态、已知工具状态、重要与近期记忆的并集（至多12条）、最近8轮交谈和约定。当前是简单检索与固定猎人人设，未接通用人格适应、向量检索或传闻传播。
- 客观事件与对话分开保存。服务端严格检查输出字段、动作白名单及引用存在性，用 HMAC 绑定世界/修订/原话/回复/建议；模型不能直接写信任、资产或事实记忆。浏览器只收到必要的回复和建议，不收到私有上下文、密钥或其他人物记忆。
- HMAC 是当前服务进程对草稿的绑定，不是外部模型真实性的独立证明。格式有效和引用存在也不证明语言理解/引用含义正确；幻觉、否定/转述误读、诱导和人物一致性须用实际模型另测。任何回复都不应成为越过动作审核的依据。
- 只实现“修理猎人工具换借用”一个协议。食物交换、抵押、任务生成、主动邀约、多人谈判与动态性格后续另立范围；本轮不重开旧 E1/Laya 筛查、微调或模型准入。
- 冷开/长历史开销、每世界128命令及有限工作机会仍存在。每次交谈也消耗一个提交名额，但不推进时间；其余协商动作每次推进10分钟。

代码入口：`runtime/core/npc-negotiation.mjs`（权威协商与知识）、`runtime-negotiation-contract.mjs`（共享格式）、`runtime/service/npc-language-provider.mjs`（可配置适配器）、`runtime-server.mjs`（签名与真实提交）、`demo-npc-dialogue.mjs`（草稿与确认）。证据及首次失败见[索引](../evidence/npc4-negotiation-provider-20261024/index.json)。

下一步先选定一个模型，在明确调用预算后用真实对话检验否定、转述、撒谎、旧伤记忆、讨价还价及上下文失效，再决定是否扩大行动词汇或增加任务类型。真实模型对话体验、浏览器外观和 Windows 启动仍是明确待验项。
