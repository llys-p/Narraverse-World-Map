# 可玩任务引导与等待反馈

## 给用户看

等待连接或执行操作时，页面现在区分“正在连接世界”“正在确认”“读取最新世界”和“展示已确认结果”，并单独显示已等待秒数。没有进度百分比或预计结束时间。秒数只用于显示，不会推进世界或任务期限，也不会重发请求。

任务板增加“下一步”、具名步骤和剩余期限：工作/购买、修好并交还工具/赠粮、森林往返、可选战斗都有明确目标。提示基于当前工作间隔、位置、口粮、战斗/行军、死亡及额度；第一章完成后会说明剩余战斗是可选挑战。未知猎人位置时只提示寻找，不读取后台位置。页面说明不再把可玩档写成128条额度。

任务面板补齐人物位置、可互动状态和战斗等刷新依赖，防止仅人物投影更新时按钮保留旧目标。前往按钮遵守现有导航额度和战斗规则；任务接取、领取和奖励仍由已保存的世界决定。

## 给接手者看

`demo-operation-feedback.mjs` 只产生显示阶段和真实经过秒数。每个活动持有独立token，旧计时回调不能覆盖新活动；每次结束、异常、隐藏和离页清理计时器。恢复可见只刷新显示，不提交命令。计时文字位于aria-live=off，避免每秒重复播报；阶段文字沿用现有状态区。显示只每秒更新一个文本节点，不触发地图重绘。

`demo-runtime-bridge.mjs` 保留原待确认请求存储、精确字节重试、DTO/回执验证、确认后刷新和清理顺序。SSE更新不会清空待确认请求或提前允许新指令；读回执后再读取世界，读到相应修订后才进入表现阶段。网络提示会区别“尚未收到回执”和“已收到回执”。页面隐藏/退出仅停止显示计时和原有后续行军，原请求仍保存在会话存储中。

`demo-playable-goals.mjs` 仅从已确认公共投影派生文案及按钮。任务期限以remainingTicks按每刻10分钟显示；到期限不擅自改任务状态。只使用当前map.actors中的可见人物，不另存任务账本。任务缓存加入下一步及人物/导航/战斗等依赖，使用新投影中的当前坐标。服务器仅在原demo静态资源白名单新增反馈模块，领域运行时、Provider、DTO和奖励规则字节不变。
