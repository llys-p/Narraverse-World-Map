# 长档冷恢复重放复用

## 给玩家看

针对从新旅程开始、命令历史连续的可玩档，尝试减少重开时的重复计算。已有历史的锚点或其他不满足条件的档案仍使用原路径。保留完整世界审计、事件和回执检查；不会自动迁移存档或重置旅程。

## 给接手者看

基于PR35提交 `f70e638ea4079f661855ff03713d1f267f0cf192`，独立分支 `codex/cold-replay-reuse-20261027`，合同 `tasks/COLD-REPLAY-REUSE-TASK.md`。完整世界历史审计仍从初始世界重放全部历史，并检查事实、随机数和末态。可玩档新路径还需满足：本次新鲜完整审计、同次实际重放的全部回执与最终事件/状态严格相等、起点与完整审计使用的原始重放起点严格相等、服务日记与已审计的完整输入历史完全相同、命令无时间或修订间隙且正好结束于末态。任何条件不成立就保留原服务日记重建。

严格重放证明只记录在进程私有WeakMap中，绑定深冻结的已审计对象；已认证增量后继不是本次新鲜完整审计，不适用捷径。证明只作观察，不允许传入跳过开关。原始日记先检查描述符并隔离；原始末态和日记与规范化对象的严格比较保护负零和原型差异，避免规范JSON与旧版严格比较的边界不一致。

涉及代理对象的输入直接回退旧路径；新增观察接口在访问属性前检查描述符。只在完整历史审计本身记录每笔重放回执、全部事件及末态的严格相等时授予进程内证据，规范JSON相等不足以触发复用。

安全范围：不改规则、奖励、存档格式、旧档转换或运行中单写者。适用范围的正确性依赖完整历史审计确实按同一个 `replayOrigin` 起点执行和核对每个结果；非适用场景、旧fixture、非连续世界时间或已有历史的锚点继续由原算法重建。不得把本片证明用于外部数据、绕过全量审计或变更信任边界。

## 本机实测

以下为同机真实worker/HTTP对照：父版各一次，7天候选一次、14天候选两次，不代表分位数、其他设备或游戏画面帧率。14天测试使用与PR34完全一致的合成存档（初始食物100），不是默认生存平衡测试；7天测试使用默认合成新旅程。两版本14天的落盘文件与五种投影SHA一致，重试回执一致且无重复写入；7天的6份文件和五种投影SHA也一致。
