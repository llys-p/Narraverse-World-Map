## 使用变化

模型已返回无效输出、超时或不可用结果时，下一次明确点击“重新生成预览”使用新请求ID；拿到有效预览后再次生成也使用新ID。点击才请求，不自动重试；失败尝试继续计入Provider原请求上限。生成、确认交谈与执行建议仍是独立步骤。

连接中断、响应不可解析、预览绑定验证失败或收到未知错误时，按钮显示“重取本次结果”，使用原ID和相同请求字节获取结果。服务仍缓存同ID的成功或失败，不因本片修改而重复请求模型。已知忙碌/预算错误也不启动自动请求。页面说明明确提示重新生成会发起新请求；模型入口默认仍关闭。

改动在 `demo-npc-dialogue.mjs` 的请求生命周期和 `demo-runtime-prototype.mjs` 的按钮文字。没有修改Provider的请求缓存、签名、输出校验、预算或超时策略。页面刷新/服务重启后的未确认模型预览恢复、通用网络取消与后台模型费用状态仍不在本片范围。

失物进展以前同时要求“失踪之后有归还来源”和“现在本人持有”。实际归还后正常借给玩家，会把旧失物从recovered错误退回not-confirmed-recovered。现在由保留的失踪与后来实际归还来源判断那次失物是否解决；当前持有人继续由knownFacts说明。

新的失踪事件仍需它之后的归还才能解决。来源被遗忘或没有实际归还时，不因玩家口述、旧交谈引用或当前本人持有就补造“已找回”；归还者仍不自动成为原先未知的小偷。修改仅为读取时派生说明，不改事件、关系、工具归属、记忆账本或存档协议。
