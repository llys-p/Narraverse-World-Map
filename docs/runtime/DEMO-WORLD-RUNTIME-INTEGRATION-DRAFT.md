## 4. 接入结构

```text
Demo三层画面、菜单、镜头、音效
        ↓ 玩家意图                ↑ 已确认状态/回合事件
有界接入模块：身份映射、展示坐标、版本对齐、固定请求恢复
        ↓                        ↑
World Runtime：订单执行、人物/资产/时间、战斗裁决、存档
```

前端持有展示状态；世界事实只由一个运行时维护。不新增第二套钱包、位置、背包或伤害裁决。优先复用已有绘制资源和命令语义，不引入前端框架或通用游戏引擎迁移。

### 4.1 三层显示

- `switchToWorldMode/SceneMode/BattleMode` 改为切换画面，不附带恢复生命、发钱、重置敌人或更改世界位置。
- `enterLocation` 需依据真实已到达地点与服务许可进入，不能把玩家坐标直接改到目标据点。
- 原型1600×920展示坐标与当前20×12权威格点是不同空间；显示投影、入口、阻挡和命中检测采用同一明确映射。不会直接把像素坐标写入现有mapModel。
- 场景内闲逛动画可以作为表现；NPC是否在场、位于哪个地点由权威位置决定。

### 4.2 订单执行与性能

- 选目的地下达一次订单，运行时持有路线并持续推进，页面不再负责逐批发MarchStep。
- 暂停/改道在有界模拟片边界生效，输入需能及时得到处理；不能将一个持续几十秒的同步任务换成后台名字就称解决。
- 运行中安全复用同一已验证历史前缀与不可变状态，验证新增转移；外部存档仍完整验证和重演。现有WeakMap证书只是可复用基础，不能据此开放外部trusted/audit-bypass参数。
- 保留原子提交、失败回滚、回执幂等及可恢复确认语义。只有证明磁盘发布成为瓶颈后，再另论日志/快照格式，先不顺带重写持久层。
- 新的持续订单不能暗中绕过128命令/文件预算；内部推进计费、停止条件与增长界限须在执行合同中明确，不能直接删限额。
- 建议第一轮沿用既有时间语义：行军与有时长动作推进世界，暂停/抵达/路遇等待及回合选指令时不推进战略时间；离页/断连停止推进，不新增离线补时。改变这一策略需单独明确。

### 4.3 回合战斗

- 保留demo的场地、人物和特效表现，替换其自动敌人AI心跳、ATB资源循环与动作快捷键裁决。
- 先消费真实已有的开始遭遇、攻击、逃跑、取消及turnEvents；未有真实规则的技能/物品指令不伪装为已接入。
- 生命、伤害、日结变化、胜负和奖励来自权威结果。切换页面、跳过动画或重新进入不能重打回合、恢复生命或重复领奖。

### 4.4 人物与资产

- `PLAYER_GOLD/PLAYER_BAG/PLAYER_STATS` 不能继续作为独立世界真源。买卖、用物品及属性变化需逐个映射至真实能力，保留无能力时明确拒绝的边界。
- 当前通用物品背包、偷窃、修炼与多种敌人不属于已有完整后端能力；需要真实规则时单独纳入范围。
- 不能只替换鼠标按钮：旧快捷键、定时器、AI回调、模式切换中的直接修改入口也必须核对。
- 服务现有同源与CSP策略同原型大量内联脚本/样式存在接入差异；需整理静态资源及事件绑定，不为省接线工作直接放开任意脚本执行。

1. 在独立树保存可回退的原型基线，冻结用户选择的真实地点/NPC范围及时间语义。

4. 只做与改动直接相关的有界核验：意图边界、暂停改道/路遇、真实资产、回合事件、失败回滚、保存恢复一致性。具体运行次数与硬时限先写执行合同，未获授权不重开旧补验或全量测试。
