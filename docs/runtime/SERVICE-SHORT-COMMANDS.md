## 给接手者看

父提交PR28 `c417dfb322cff2880e81f746c0fded608b24f567`；工作树 `Narraverse-Short`，分支 `codex/service-short-commands-20261026`，合同 `tasks/SERVICE-SHORT-COMMANDS-TASK.md`。

生产改动五处：

- `command-engine.mjs`：只有系统键和函数均为自身规范处理函数的campaign会话可复用 `createAuditedBundle` 的私有不可变证明。原始输入仍完整审计并隔离，自定义系统保持旧路径；公有方法、tick引擎、规范系统和回滚/统计逻辑不变。
- `bounded-json-file.mjs`：复用原 `parts` 的排序及JSON片段，一遍遍历、逐片检查64MiB限额，约64KiB聚合后一次合并。字节格式与旧版一致；暂存缓冲总量≤一份文件，最终合并时额外保留至多一份文件大小的缓冲。原 `publishStateFile` 仍返回路径，新辅助函数仅在成功发布后返回事先计算的完整字节指纹；临时文件、fsync、独占链接和清理顺序不变。
- `service-commit.mjs`：指纹只在当前拥有者内缓存。每次前后均检查锁、文件预算、最新修订并完整读文件；首次或字节变化时严格解析比对，未变时省去重复解析。成功发布后同步推进指纹和head，失败/不明不推进。无持久侧文件、可传入指纹或新增信任开关。
- `world-state.mjs` / `http-contract.mjs`：两个投影的前置数据树扫描可复用已有私有不可变证明，规则验证仍保留；原始、复制、伪冻结或代理包裹对象仍完整预检，未知元数据与访问器的拒绝顺序不变。

编码实验：直接调用规范编码器很快，但不能据此省去提前字节限额，未采用；保留预扫描再规范编码仍有双遍历成本，也未采用。最终复用原片段生成器分块，保留原字节序及超限提前停止。快路径不靠mtime或文件大小，不能只测缓存命中而省掉变更处理。
