完整末态审计会从种子和配置重放历史、核对事件及世界；服务日记从锚点重新计算每条命令，核对回执及最终数据。两者存在重叠，不能仅凭时长把其中一项删除；对于已有历史的锚点、未记录命令、事件和回执篡改等场景，必须证明同等校验后才能尝试优化。

本合成样本中，锚点为第0刻、无事件和输入，服务日记与末态世界内的输入历史逐项相等；这不是所有合法存档都满足的定理。可研究的方向是在同一次恢复中复用末态审计已经产生并验证过的重放事实：仅当完整锚点、输入顺序、每条DTO/回执、事件和最终状态之间的对应关系都得到证明时，才使用已有结果；否则回退当前逐条重建。证明应由本进程私有、不可伪造、限本次恢复的对象承载，不从存档字段或调用者标志授信。
