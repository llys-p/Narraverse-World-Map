# NPC8：独立的记忆更新与回忆

2026-10-25（Asia/Shanghai）。从PR #15的 `c14a07e5a6c93e59d699adcb37fdb8577110b194` 建立独立候选。2.0只用作设计参考，没有复制、导入它的人物记忆、资料卡、模块或存档。本片实现本项目自己的更新流程。

## 使用入口

Windows运行 `Start-NPC-Memory.cmd`，打开 `http://127.0.0.1:18350/demo-runtime.html`。新世界profile为 `campaign-memory-village`，独立数据目录 `artifacts/npc8-memory/world`；关闭时输入 `quit`，等 `stopped` 后再重开。既有NPC入口仍读取各自的原档。

也可在本候选目录运行：

```sh
node --env-file-if-exists=.env runtime-server.mjs --data-dir artifacts/npc8-memory/world --profile campaign-memory-village --seed 42 --writable true --continuous-march true --port 18350
```

上面命令只用于创建新目录；重开已有目录时去掉 `--profile` 和 `--seed`。模型入口仍默认关闭，配置规则沿用本项目NPC4/NPC6说明。此次没有写入凭据或调用外部模型。Windows启动器与真实浏览器外观尚未实测。

## 怎样更新记忆

1. 世界先执行并确认行动，沿用已有距离、目击、物品与关系规则。
2. 每位NPC只把自己已经获得的观察追加为经历，保存事件编号、游戏时间、来源，以及当时已知的持有人和耐久。没有看到偷窃的人不能凭账本知道小偷。
3. 已确认交谈另存为“双方说过的话”。未确认预览不写入；玩家说“已经修好”不产生修理事件。当前只有猎人接自然对话，其他NPC不会收到这份私聊。
4. 读取时按当前话题检索相关经历和后续事件，再结合NPC当前已知状态形成带引用的进展说明。原事件保持原样。
5. 同一来源只处理一次。重试、保存重开、重新检索、重新派生说明不重复改变关系或追加经历。

| 实际过程 | 现在记住的内容 |
| --- | --- |
| 玩家砸坏工具，后来实际修好 | 曾经受损与当前已修好同时保留，修理不自动等于原谅 |
| 玩家道歉，再反复道歉 | 记录收到道歉及重复/拒绝结果，不推断已赔偿 |
| 无人看到偷窃，后来发现失物，再有人归还 | 保留未知作案者与实际归还者，两者不自动等同 |
| 借用逾期后归还 | 保存归还进展，也保留失约；迟还分钟数按实际归还时刻固定 |
| 玩家口头声称已修好或指认别人偷窃 | 仅成为交谈记录，不改物品状态或观察事实 |

经历最多64条，猎人的交谈最多16轮；超过上限时记录累计遗忘数量。经历保留最近8条及每类最近的关键事件，再优先淘汰低重要性的旧记录。模型每次最多收到12条相关经历、最近8轮交谈；话题匹配目前是有限中文关键词规则，不是通用语义检索。旧伤害较多时仍保留相关修理/归还等后续引用，避免只召回伤害。

这是有界记忆。保留16轮交谈不代表每次发送16轮，也没有对更早交谈做全文搜索。被淘汰的细节不能补造；遗忘计数不能恢复旧原文。当前衍生进展覆盖损坏、失物、逾期和道歉，不声称能自动理解任意事件、建立复杂信念或传播传闻。

## 代码与兼容边界

- `runtime/core/npc-memory.mjs`负责世界拥有的私有经历/交谈、去重、保留策略、校验、话题检索与进展派生。核心更新不调用模型，也不让模型写关系分数。
- 新fixture5/map5通过场景提交钩子接入；原social工作记忆和关系规则继续运行，新档另有独立记忆账本，并在32条工作窗口中保护最近8条观察，保证新观察先进入账本。fixture1至4不自动升级，旧世界没有新字段。DTO5、service format11、公开地图投影3保持原协议。
- `npcDialogueContext`和Provider只读猎人的记忆；公开页面投影不暴露原始账本、进展说明或私有已知事实。模型仍自由生成回复，按钮交谈仍是原有确定性回应。
- 全量重放核验记忆与事件一致。结构校验只检查形状、来源单调性和当前观察一致性，不能单独代替重放审计。
- 新模块也纳入既有评测CLI的源码指纹。CLI现有8场景仍创建fixture4；其plan运行只证明旧评测通路可运行，不是NPC8自然语言评测。
