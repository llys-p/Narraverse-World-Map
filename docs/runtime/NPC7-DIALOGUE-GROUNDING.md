# NPC7：让模型读懂可知事实与当前意图

2026-10-25（Asia/Shanghai）。接 PR #14 的真实开发评测：8 场景/16 轮 HTTP 成功，自动14/16，逐句检查仍有身份、目击、时长与建议错误。本片修复模型输入和提示，不把离线结果写成模型语义通过。

## 这次改了什么

| 原实测问题 | 本次处理 |
| --- | --- |
| actor-2持有工具，模型却说工具不在自己手上 | 明确actor-2为猎人本人、actor-4为玩家；派生self/player/unknown及解释，不推断工具实际位置 |
| 亲历破坏被玩家否认后说成“没有亲眼看见” | 为所选记忆明确self亲历、witness目击、discovery事后发现；与交谈记录分开，未知行为人保持未知 |
| 迟还20分钟说成两小时以上 | 引用统一时钟常量，每刻10分钟，由程序算好；归还后按closedTick固定时长，尚未归还时用当前时间 |
| 修好待领取却暗示已经借出 | 分开说明repairRecorded、readyForSeparateClaim、wasClaimed与wasReturned；修理记录不等于交付 |
| 询问已有条款时又生成协商，明确现在修理却漏掉help | 为少量完整句式提供existing-terms-question/repair-now提示；否定、转述、引语、过去完成和条件句不靠删词匹配 |
| 多个话题机械转回修理换借用 | 提示先回答当前话题，移除以修理协商作为唯一完整回复示例；旧回复有误时按当前可知事实纠正 |

派生层只读取原来允许发送的 NPC 私有视角，不查询世界的真实持有人或其他人的记忆。未知失物仍为未知；不会通过新增字段让 NPC 获得未目击事实。原来至多12条近期/重要记忆、8轮交谈和32KiB入口预算保持；自定义的未声明字段不会发给模型。

`runtime/service/npc-dialogue-grounding.mjs` 提供同一个准备函数，Provider和评测器都传入本轮原话。转换重复应用结果不变；报告记录的上下文与实际请求一致。源码指纹包含新派生层、有界文字解析器和时钟常量。

## 仍由模型完成的部分

这不是固定台词表。回复仍来自所选模型；本层不改写模型措辞、不伪造或补齐模型返回的行动建议。完整句式提示只覆盖少量明确表达，未覆盖的表达仍交给模型理解或追问。既有结构/引用校验、签名、预览、交谈确认和单独行动确认继续生效。

新的提示不能保证模型每次正确使用事实。结构有效但内容错误仍有可能出现，真实质量须另测；不能把“程序算对20分钟”称为“模型已经不会说错”。完整上下文更长，也可能更早达到原有输入预算，未测实际token成本变化。
