# NPC10：短追问的记忆检索承接

2026-10-25（Asia/Shanghai）。从NPC9 `0150106f29a01573a82a0e0ff31472e1e005a975` 建立 `codex/npc10-followup-recall-20261025`，叠在草稿 #17 上。

## 功能与边界

原检索只匹配当前句的关键词。当已保留的赠粮经历被较多高重要性伤害挤出12条模型上下文时，先问粮食，再问“那后来呢？”会丢掉相关赠粮来源。两项回归先在NPC9代码上失败；NPC10只改变读取时的检索话题，不增加或改写经历。

fixture5首先使用当前原话的已有话题。没有明确话题且完整句匹配“那后来呢”“那现在呢”“还有呢”等有限追问时，从模型同样可见的最近8轮已确认玩家原话向前查找。可越过连续的受支持追问；遇不支持的问句或闲聊立即停止。新的明确话题优先。窗口以外的交谈、未确认预览和旧NPC回复均不能成为锚点。

`runtime/service/npc-recall-focus.mjs`只返回查询文本及 `recallFocus`：固定来源枚举、已有话题枚举、锚点交谈编号。字段只在私人Provider上下文中派生，不写存档或公开投影；检索仍最多12条经历、最近8轮交谈，Provider仍限制32KiB。旧fixture1～4没有新增字段或改变检索规则。

话题相关不证明事件发生。口头“送过粮食”可以让短追问检索粮食相关经历，但没有赠粮事件就没有可恢复的事实。被遗忘的来源即使还出现在旧交谈的引用数组中，也不能再次作为已提供来源引用。现有协议允许引用保留的交谈编号来说明“曾经说过”，这不等于事件证据；本片保留该协议。

实现不推断行动意图、不补proposal、不直接执行。上下文说明要求模型在指代不明时澄清，但没有通用语义判别器，无法保证模型措辞正确或停止跑题。短句集合和已有中文话题词仍有限；不等于通用多轮理解或长期摘要。

新测试包含5项读取/Provider边界、1项真实本机HTTP/worker保存恢复、2项评测接线。拥挤窗口使用明确标注的合成私人上下文；真实消费者使用实际赠粮、预览、确认交谈和文件保存。
