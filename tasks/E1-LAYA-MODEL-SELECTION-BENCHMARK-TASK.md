# E1 预研任务书：Laya 多版本 NPC SocialSignal 对照测试与选型建议

发布时间：2026-10-07 11:23（Asia/Shanghai）。任务状态：旧 E1 预研路线已收档；当前筛查无信号达到继续投入门槛，正式 Runtime 准入为空。此结论不表示任何模型已通过 Runtime 准入；详情见 [PROJECT_CONTEXT.md](../PROJECT_CONTEXT.md)。

## 1. 交给执行者的目标

在独立、可复现的离线试验中，用**同一批 Narraverse 中文 NPC 社会交互样本**测试三款 Laya checkpoint，提交逐信号结果和一份可审查的选型建议。回答三件事：哪款现成模型更适合哪些 SocialSignal；它能否在计划部署环境运行；若均不达标，是否值得以官方 multilingual 为底座另开自有数据微调任务。

本任务只做 benchmark 与决策报告，不修改 World Runtime、NPC 行为规则、旧 Laya 桥或正式 Narraverse。A→B→C→D→E 的实施顺序不变。执行者不自行宣布 E1 已验收，也不因某个模型自报分数高而接入产品。

## 3. 工作包与交付顺序

| 工作包 | 产物 | 完成条件 |
|---|---|---|
| M0 来源与可运行性 | 候选清单、revision/哈希、许可与依赖表、实际硬件说明 | 明确 A/B/C 是否能在当前设备原样运行；区分模型卡自报与本机验证 |
| M1 数据与标签 | `benchmarks/npc-socialsignal/` 下的样本、标签规范、来源说明与切分清单 | 标签只依据 Actor 可知事实；独立复核分歧；最终测试集隔离 |
| M2 统一评测器 | 可重跑命令、配置锁定文件、原始逐例预测、校准过程 | 同一输入/问题/选项定义覆盖 A/B/C；失败和超时有记录；没有产品写入 |
| M3 对照测试 | 逐信号指标、成对差异、不确定性、错误案例、硬件耗时 | 三款实际结果分别标明“已测/未测/不可比”，不混用不同测试集 |
| M4 决策报告 | 逐信号准入建议、部署可行性、后续微调建议与复现步骤 | 给出一个当前预研默认候选或“证据不足”，同时列明无法进入 Runtime 的信号 |

各工作包可由不同 AI 分担，但 M1 的样本定义和 M2 的问题模板必须先冻结，M3 才能打开最终测试标签。数据/评测器由一位执行者整合，避免多版本各自改题；另一位 AI 可做盲审或独立复核。提交前留出源码审查与重复样本检查。仅在新建的 `benchmarks/npc-socialsignal/` 写数据、脚本和报告；若确需改现有文件，先列出具体文件与原因交中控审核。

## 4. 数据与公平比较合同

- 目标 300～500 个**独立场景**，其中最终盲测至少 150 个；若少于 300、某关键信号/类别最终样本少于 20 个，仍可交探索结果，但该类标“证据不足”。按场景家族、人物关系与措辞模板切分开发、校准、最终测试，近似改名样本不得跨集合。保留每个集合的数量、标签分布和内容哈希。
- 核心五信号：`social_act`、`trust_shift`、`fear_shift`、`deception`、`boundary_violation`。`hostility`、`credibility` 可作扩展层，先写标签定义再纳入；不因扩展层表现好掩盖核心失败。
- 每个标签给中文定义、Actor 可见证据、正反例、`信息不足/不确定` 的使用条件。`trust_shift`/`fear_shift` 只判方向，不写入实际数值；`deception` 只判可见欺骗线索，不推断无法观察的真实意图。覆盖否定、讽刺、礼貌威胁、多人物指代、矛盾线索、身份/关系差异、边界未告知、中文夹英文与长上下文截断。
- 样本由执行者创作或使用明确获准的数据；不复制真实玩家私聊、旧存档、未授权剧情或其他仓库敏感资料。标签不能仅由待测 Laya 生成。至少两次相互独立的盲审，记录分歧及裁定；若无法安排独立复核，报告只能给**暂定预研排序**，不能声称可靠选型或生产准入。
- 三款模型收到相同的 Actor 可知上下文、问题、候选语义与测试 ID。实现差异只限 SDK 所需适配，并在报告中列出。先以短输入和少量 `choice` 测主结果；统一 1024 token 内的实际输入预算与截断规则，另做长输入敏感性测试。对选项次序置换、等义改写、信息不足和空/异常输入分别给稳定性结果，不能把格式错误静默改成正确回答。
- 开发集可改问题模板；校准集只用于拟合置信度/拒答阈值；打开最终测试结果后不得再调题、改阈值或删难例。若修改方案，重新版本化并留出新的盲测集。保存逐例预测、原始分数、已校准分数、模型错误与超时记录，便于独立复算。

## 5. 指标与决策规则

每个信号分别报告样本数、类别分布、准确率、macro-F1、混淆矩阵、信息不足/拒答覆盖率、接受子集错误率；有可解释概率输出时报告 Brier/ECE，校准方法和数据集必须写明。`deception`、`boundary_violation` 等高风险信号另列假阳性/假阴性和具体反例。至少加入多数类与简易规则基线；用**按场景配对**的差值及 95% bootstrap 区间比较模型，不能把三款不同作者的模型卡分数相减。按短/长输入、选项次序、人物关系和标签分层，指出失效范围。

先看许可与计划部署环境是否可行，再逐信号看误判风险、可校准覆盖率和相对基线提升；准确率接近时选择依赖更少、可在目标设备离线运行的方案。没有清晰的成对优势时写“无法区分”，不强行排第一。对安全敏感信号，只要样本量不足或危险误判仍不可接受，就建议禁用/走确定性 fallback；**预研第一名不等于可接入 Runtime**。`mia-laya` 的情感分数不与主五信号总分相加。

C 若只能在 Apple Silicon 上运行，允许用相同冻结样本比较其**预测质量**，但吞吐/延迟必须按各自硬件分开。若执行者只有 Windows/NVIDIA，则标 C“当前环境未测”，不得凭模型卡成绩选它作本机部署方案；若制作转换版，须另列身份并先证明同样输入与原 MLX 输出等价，不能把转换版结果记成原版。A/B 即使胜出也需有本机离线运行证据，才能推荐为实施候选。

报告末尾必须给出三层结论：①当前实验默认模型（或证据不足）；②每个 SocialSignal 的可继续评估/需微调/禁用/证据不足；③是否另开 `laya-narraverse-social-v1` 微调任务。若现成候选都不够好，优先说明以 Apache-2.0 官方 multilingual 为底座的理由、训练数据与许可条件；**本任务不执行 fine-tune**，也不提前写 E2 Adapter。
