## 问题与目标

现有 `json()` 将所有非成功 HTTP 响应标作 `confirmed`，`perform()` 随即清除请求；但服务器/工作线程故障不能证明行动未持久化。另外，成功回执在后续状态刷新之前就清除请求，刷新失败会丢失恢复入口。

1. 网络错误、5xx、限流/超时、未知或不合协议的错误响应保留原始请求字节与 ID；新行动继续受阻，只能显式重试原请求。
2. 只有匹配现有 API 合同的确定拒绝响应可以终结该次 POST；读取状态的错误不能终结行动。
3. 有效成功/领域拒绝回执须配合不早于该回执的同一世界投影，并完成消费者通知后才清除待确认记录。
4. 刷新/正常服务重开后，保全记录仍可恢复；重试不重复卖出、扣粮、推进时间或增加正式存档。
