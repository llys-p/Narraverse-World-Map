# D4E11 设计草案：自主地图旅行与日式回合制战斗

2026-10-17（Asia/Shanghai），v0.1。**用户目标已确认；本文件待用户审阅，尚非冻结执行合同，未开始生产实现。**

## 给用户：这一版将怎样玩

你在大地图上点击可通行的位置，玩家沿路线移动过去；不限于点村庄/森林两个入口。路程会消耗真实世界时间和疲劳，当前位置会随存档保存。抵达村庄可以进入地点互动，在森林可以主动进入遭遇。

战斗采用独立的日式RPG画面：左侧玩家、右侧狼，下方指令菜单。选择攻击，播放接近→挥砍→受击；狼若实际反击，再播放反击；倒地与胜负按真实结果显示。动画结束回到下一回合指令，胜利/逃跑后回到原地图位置。攻击、逃跑继续使用现有规则。

**建议第一版采用“每次点击完成一段旅行，抵达后再选下一点”。** 移动请求完成前显示路线与等待状态，确认后播放此次行程；第一版没有途中改道/中途存档点。途中可随时打断的持续行军需要另一套行军订单与分段提交，暂不混入本版。战斗也不加入实时移动/格挡/挥砍操作。

```text
点选地图位置 → 真实旅行/抵达 → 进入村庄互动或森林遭遇
                                      ↓
                         选择指令 → 播放本回合 → 下一回合
                                      ↓
                              胜利/逃跑 → 原地图位置
```

## 1. 方案选择及成本

| 方案 | 用户得到什么 | 成本与取舍 |
|---|---|---|
| A：真实坐标、按段旅行、回合制战斗（推荐） | 任意可通行点移动、按距离耗时、保存位置、JRPG回合演出 | 沿用单命令原子提交，增加有界地图和新存档版本；一段确认后再接受下一段 |
| B：持续行军，途中暂停/改道 | 地图上持续走动、随时改变目的地 | 需持久行军订单、分段结算与取消语义；高频审计/提交与128命令预算有直接冲突，须先定性能和档案预算 |

本草案选择A。它新增真实地图能力，不将前端自由行走原型的坐标当作权威位置；也不扩展整个商队/派系/实时NPC移动系统。对旧profile和旧存档保持原来的精确规则。

## 2. 地图与世界事实

- 一张固定、版本化的20×12逻辑格地图，画面隐藏格线；以地形、路网、桥和地点轮廓呈现。村庄中心(4,7)，森林入口(16,7)，玩家初始在村庄中心。数值为本轮原型参数，不代表真实地理比例。
- 村庄区域为x=3..5、y=6..8；森林区域为x=14..19、y=2..11；其余可通行格为road（野外道路/原野）。河流列x=10，仅y=7的桥可穿越。出界和水面不可抵达。人物权威地点由坐标和地图规则唯一派生；三NPC继续固定村庄。
- 四邻接最短路，固定邻接顺序北/东/南/西消除同长路线歧义；搜索最多240格，单次路线最多48步。客户端可预览，但服务端独立重算路线、成本、终点和区域，不能信任客户端时间、距离、位置或疲劳字段。
- 每步1 tick（现有世界1 tick=10分钟），一次移动疲劳增量为ceil(步数×100/12)，上限仍1000；村庄中心到森林入口恰12步、12 tick、疲劳+100。分次移动各自向上取整，不承诺与一次直达疲劳完全相同。
- 沿用当前有时长动作的事务语义：开始位置保持到完成tick，完成时先落地目标坐标/区域，再执行该tick既有日结；不新增中途可交互状态。如果日结等原因在完成前使玩家死亡，完成拒绝、位置保持起点，已经过去的时间/日结保留。
- 相同位置、不可达/超过路线预算、死亡、遭遇占用按真实拒绝语义处理；无有效移动时不扣疲劳。不新增自动野怪、路遇奖励或假NPC移动。
- 地点互动以权威区域判定：村庄可工作/买卖/赠粮；森林可发起已有遭遇；road不能隔空使用村庄服务或发起森林遭遇。查看异地页面继续只读空态，不能造成旅行。
- 地图仍由明确输入推进时间，停留/拖动镜头/刷新不推进世界。请求中禁止并发世界写；失败不前移；播放行程时可跳过表现，跳过不再移动/扣时/扣疲劳。刷新/重开直接显示已确认终点，不自动继续旅行。

## 3. 最小接口与持久化设计

- 新opt-in profile `campaign-village`、rules `d-campaign-v1`、serviceFormat11、command DTO5/receipt5；旧1..10格式及DTO1..4语义保留。不迁移、导入或覆写旧日常世界。
- 新世界增加精确形状的 `mapModel:{version:'campaign-map-v1',mapId:'village-forest-v1',position:{x,y}}`。新actor-config-v5允许玩家在village/forest/road，NPC仍只准village；新memory-config-v8/society-config-v7与该地图profile精确配对，玩家工资账沿用player-state-v4，不无故增加玩家资产版本。
- 新 `PlayerMapMove` 使用原命令通道：`{version:5,commandId,expectedRevision,type:'PlayerMapMove',payload:{x,y}}`。payload只收安全整数坐标；拒绝注入cost/path/time/outcome及未知键。新profile的地点往返按钮也发送该命令到地点中心；不保留新profile中固定12 tick的旧快捷旅行旁路。旧profile的PlayerTravel原样保留。
- 成功result精确为 `{actorId,from,to,path,steps,fatigueCost,before,after}`；from/to为坐标，path含首尾、长度steps+1；before/after只含实际location/fatigue。时长使用顶层durationTicks=steps。业务拒绝保持现有 `{code:reasonCode}`；无效输入4xx无提交。同一完整DTO幂等返回原回执，同ID异DTO冲突。
- 增加只读 `/api/runtime/map`，仅新profile可用，返回 `{apiVersion:1,mapViewVersion:1,simulationId,revision,tick,mapId,width:20,height:12,blocked,landmarks,self:{actorId,x,y,location,alive},movement:{maxSteps:48,ticksPerStep:1}}`。blocked为固定有界格坐标，landmarks精确村庄/森林入口。capabilities明确mapAvailable、mapViewVersion、DTO5；旧profile不宣称有地图坐标。
- 原player/scene/encounter投影在新profile显式支持road及新规则；所有页面同simulationId/revision/tick组校验后再更新。旧页面DTO3/4路径保留。活动最多64条/来源256条/65536字节不放宽，地图坐标不自动作为NPC知识。
- 移动起点、目的地、规范路径、成本、最终位置和回执全部从规范初态/有序输入重演核对；篡改坐标、路径、疲劳、耗时或回执，即使重算外层指纹也拒绝。发布失败保持原内存/磁盘/坐标；坏最新正式档显式失败，不回退旧位置。

## 4. 日式回合制战斗与表现事件

- 进入森林遭遇后显示大幅战场背景、玩家/狼、姓名/HP、回合指令区。攻击先选狼，再确认；目标选择/返回菜单不提交、不扣时间；逃跑使用现有真实命令。只呈现可用的攻击/逃跑，取消遭遇保留既有规则入口，不假设已有技能、MP、道具战斗或队友。
- 现有150攻击、80存活狼反击、6 tick每攻击/逃跑、死亡/预留/生态账与两次攻击胜利规则保持。输入菜单是玩家操作时间，不让世界按墙钟自行流逝。
- 状态为菜单→目标选择→提交中→回合播放→菜单/战斗结束。提交期间和播放期间不再接受攻击；待确认固定DTO存到原pending路径，重试复用同ID，迟到/失配组不得覆盖当前世界。
- 新receipt5的EncounterAction成功result增加有界 `turnEvents`（至多6条），精确事件 `{kind,actorId,targetId,beforeHealth,afterHealth}`。kind为player-strike/wolf-counter/world-settlement/defeat/flee；不相关HP字段用null，身份仅本人或本次encounter狼。生成时记录真实规则执行点的前后状态，顺序由服务决定并被完整重演校验；旧receipt3/4精确形状不变。
- 玩家攻击/狼反击的HP记录取完成tick内真实战斗计算前后；随后日结的HP变化独立标记world-settlement。完成前死亡导致攻击未落地时，不能生成player-strike/wolf-counter。前端不能从整条命令净HP变化推造反击、伤害、MISS或暴击。
- 表现按真实turnEvents排队：玩家靠近/挥砍→狼受击与真实数字→仅存在反击事件时狼扑击/玩家受击→死亡/胜利。击杀回合不播放死狼反击；减少动态直接末态；事件不足的旧profile使用D4E10前后状态表现，不推算新事件。
- 动画使用已有火柴人/狼绘制资源、rAF/可取消WAAPI和捕获代次；刷新、新revision、离页、跳过/停止均使旧回调失效。命中停顿与镜头反馈由本表现层控制，不使用旧WorldFX不可取消计时器。所有美术只借已有素材/自绘背景，不引入付费模型或来源未明资源。
- HP/动作/指令为主画面；完整JSON与开发者观察折叠到详情。HTML菜单支持键盘、姓名/HP文本可读；图形失败保留真实操作和结果。手机适配不开展。

## 6. 实施顺序、所有权与最少验收

实施时从已验基准 `6c60fe2d5b6276660936e1ab55a43385a79737ba` 建独立执行分支 `codex/world-runtime-campaign-jrpg`；拟树 `D:/Narraverse-World-Map-campaign-jrpg`。先核对目标不存在及实际worktree状态，不覆盖旧树。先完成一条真实地图旅行/保存链，再接回合表现，最终同一世界跑通两者。

| 片 | 交付 | 最少证明与停止点 |
|---|---|---|
| A 地图权威链 | 固定有界地图、坐标与新profile、Move命令/投影/审计/保存，现有地图页面消费 | 路径/阻挡/费用/区域门/输入注入与版本边界；一个真实owner新世界移动到非地点坐标，再正常重开，原坐标/路径/回执/档SHA一致 |
| B 回合链 | 真正执行点turnEvents、JRPG指令菜单和表现 | 首回合攻击/反击，击杀无反击；跨日结不能冒充战斗伤害；旧receipt无新键，新回执篡改拒绝 |
| C 同世界消费者收口 | 地图→村庄→任意道路点→森林战斗→返村→重开 | 真实页面输入/控制台/权威状态，恢复同坐标同人同结果；原档和既有服务保护。外观仍按用户约束标未验 |

核验只做受影响的最少定向成员，不跑全量/长历史/无关/视觉。核心纯检查父限60秒，服务定向成员各180秒；根消费者每阶段120秒、总600秒、退出确认5秒。不得因超时自动重跑整条故事；保留首败，定位后按直接改动补验。若最少完整审计也超限，先交回原因/预算裁定，不削弱校验。

另用一个最小定向服务成员在同一隔离fixture验证持久发布失败回滚/重试、坏最新档或坐标篡改拒绝；复用未改核心的旧账/记忆证据。涉及完成tick顺序的当前直接修改，必须补一例攻击跨日结的事件归因和一例旅行完成前死亡，不跑旧长链。

高耦合规则/版本/审计由根负责，机械页面/绘制接线可按文件单写分配性价比子模型；无DSH。此草案不发执行工单、不派工、不启动服务、不记已实现。
