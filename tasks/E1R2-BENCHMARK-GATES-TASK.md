## F1：完整性错误必须拒绝，不能产出正常成绩

位置：`scripts/score.py` 的 `load_preds`、`score_signal` 与 CLI。

本轮反例：重复预测与 NaN 概率产生 **15 条问题，但 CLI exit=0，仍写正常 scores**。两条计划场景只有一条金标时，`score_signal` 过滤掉另一条，得到 planned=1、accuracy=1.0。runner 写 `*.e1r.jsonl`，scorer 却读 `*.jsonl`：仅存在新产物的临时目录，scorer 返回找不到文件；现有完整重算实际消费的是旧 pilot raw，不能证明新 runner→scorer 已贯通。

验收：

- 校验金标与计划场景 ID 精确一致且唯一、五信号完备、合法；缺失/多余/重复金标明确拒绝，不能缩分母。校验预测所属模型/切分/条件/场景/信号及唯一键。
- 通过显式运行清单/产物路径统一 runner→scorer→校准锁的消费链；仅有新命名产物也能评测，不能静默消费同名旧 pilot。加入无模型合成输出经CLI完整评分的消费者回归，锁内记录实际预测文件哈希及运行配置。
- 重复预测、非法概率（含非有限 confidence、概率类型/类别键不匹配）使正式评分/拟合非零退出；可写单独诊断错误文件，不能发布有效分数或改写校准锁。
- 缺失预测、超时和非法 label 仍按全量计划计错；预测文件为空/模型全失败也要有明确全量失败报告，不能假装没有计划。
- 对正常存量重算保持现有准确率；固定类别口径由同一份计划金标决定，零支持处理须显式记录。

## F2：冻结必须绑定真实回执和运行方案

位置：`scripts/score.py:verify_freeze_gate`、`scripts/run_bench_v2.py`。

本轮临时副本中填正确四件哈希，但复核者写 `['same','same']`，裁定人身份与“非原标注人”声明缺失；传入未知模型 Z、未知条件 invented-pressure，gate 返回 **空错误列表**。原代码只拒绝 `adjudicator_is_original_annotator is True`，缺失值反而通过。

验收：

- 两名不同且非空复核者身份、各自签署的未接触答案/独立性声明、回执文件哈希与样本覆盖；裁定人身份、裁定完成回执、显式非原标注人声明必须齐全。类型不合法或缺失 fail closed；布尔值和姓名自填不是证明独立性的全部证据，中控仍须核对回执。
- 冻结 LABEL_SPEC、切分/输入、外部金标哈希、问题模板、实际候选/runtime 配置与校准/阈值；绑定模型集合、条件集合、选项顺序及 max_len/head_max_len/截断策略/样本范围。运行 CLI 改配置或 `--limit` 不能绕过已冻结方案。
- runner 和 scorer 使用同一份 final 输入源及 ID；当前 runner 读 blind 成品、scorer 从 src-batch 重建，必须消除不一致或逐项一致性拒绝。
- 记录 final 运行身份与开启状态，拒绝未经预注册的新条件/重新开启；一次预注册实验可以包括多个候选与压力条件，不能把第二个候选误判为第二次偷看。重复评分既有产物可幂等，但不得重拟或替换预测。
- 不创建假的正式 gate 以过测试；只在临时 fixture 中注入回执反例。正式 final 继续保持未开放。

## F3：超时要终止工作，不能留下推理线程继续用同一模型

位置：`scripts/run_bench_v2.py:predict_with_timeout` 及 chunk 循环。

本轮合成 agent 两次 5ms 超时返回后，仍有 **2 个工作线程同时执行、随后完成**；`join(timeout)` 仅限制等待，不是杀掉计算。继续下一 chunk 会并发调用同一 agent 并放大资源占用。

验收：

- 使用可终止的离线 worker 边界，或有真实可验证的取消机制；超时后终止并回收原 worker，再处理后续批次。不要新增通用调度平台。
- 超时错误及时保存、该批按计划计错；未处理批次也要有明确失败/未执行记录，不回退 primary，不覆盖旧运行产物。
- sleep/hang 合成 worker 在短超时内测试：没有遗留进程/线程继续计算、没有后续重叠，已完成记录可恢复。空结果/短结果/畸形结果同样记录错误，不能索引崩溃丢整次结果。

## F4：截断守住预算、可见事实和重新标注边界

位置：`scripts/inputs.py:assemble_with_budget`、runner、scorer、`stability.py`。

本轮八条历史的合成样本：预算100，返回458 tokens，仍留四条历史，却先删边界。循环用 `len(history)>len(removed)` 导致删到一半提前停下。边界删除后文本变成“该 NPC 从未被告知相关规矩”，把信息缺失改写成确定事实。另将 `requires_relabel=true` 输入评分器，仍按旧金标得1.0。

验收：

- 最旧历史持续删到预算满足/历史为空，再按政策处理边界；不能把“被截掉”表述为“从未知道”。NPC/当前话轮不能删且仍超限时，明确拒绝或进入预注册的单列路径，禁止 SDK 静默截断后仍称输入一致。
- primary 与各条件都校验实际 state/head/总预算和最终输入；保存截断前后计数、删除行及原因。`decisive_evidence` 使用按信号可追溯的文本/行引用，不把作者标签提示传进模型或盲审包；final 对应依据留在外部标注件。
- 依据丢失时原标签不得进入正式条件评分：先独立重新标注截断后的可见文本，或标该条件未完成/仅诊断。正式可评分子集如有变化必须预注册并显示全量覆盖，不能偷偷缩分母。
- 稳定性分母也以预先计划的对照项为准；缺失/双方失败不能跳掉以抬高一致率；人工等义改写未经独立确认时仍只作诊断。
