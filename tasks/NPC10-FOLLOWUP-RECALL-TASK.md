# NPC10：已确认交谈的话题承接

从 NPC9 `0150106f29a01573a82a0e0ff31472e1e005a975` / 草稿 #17 建立独立分支 `codex/npc10-followup-recall-20261025`。用户要求继续推进；本片不调用外部模型。

## 给用户

修复“那后来呢？”等短追问没有话题关键词，导致上一轮相关经历被其他高重要性记忆挤出的缺口。承接只帮助检索，玩家说过的话不会变成发生过的事实。

## 给 AI

- 先用拥挤的合成记忆窗口复现：赠粮仍在私人账本，但短追问漏选。
- fixture5 当前原话明确命中已有话题时优先当前话题；只有有限整句追问才可沿最近8轮连续、已确认的玩家原话寻找锚点。遇新话题/不支持句式停止，不读取模型回复做话题，不把引用编号当事实来源。
- 输出固定话题枚举、来源类型及锚点事件号，不能新增事实、动作建议、持久字段或存档协议。保持12条经历、8轮交谈和32KiB上限；旧fixture行为不变。
- 验证连续追问、明确转题、无锚点、窗口之外、引用/否定/附加动作、错误旧回复、遗忘来源、幂等与零写入。真实HTTP/worker验证未确认预览不构成锚点，确认、重开后可承接，来源私有且同DTO重试不重复写。
- 保留旧证据及其他工作树；新源码、测试日志和失败记录建立独立索引。准备具体后续真实测试范围，不用受控输出声称语言质量通过。

## 停止点

通过定向回归和消费者验证后更新当前状态，交叠在 #17 的草稿PR。不合main、部署、迁移真实存档或启停日常实例；控制树/Projects待主线复核。
