# NPC5 单猎人连续对话开发场景

这是 8 个作者自写公开场景、16 轮对话，用于在接入模型后复现具体问题。不是盲测、独立金标或旧 E1 模型准入；本次没有真实模型、语义质量、费用或速度测评结论。

当前项目仍未配置 `NPC_LLM_BASE_URL`、`NPC_LLM_MODEL`、`NPC_LLM_API_KEY`。本轮交付评测入口与受控协议验证；真实调用需要明确的服务、模型与测试调用范围。密钥只在本项目 `.env`/进程配置，不能放进仓库或评测数据。

## 场景与检查

| 场景ID | 轮数 | 要检验的行为 |
| --- | ---: | --- |
| bargain | 3 | 提议20点/一天，正式还价后记住40点/半天；口头声称修好不当履约 |
| help-memory | 2 | 明确提出修理；后续真实修理完成后记住做过什么 |
| negation-report | 2 | 否定、引语、转述不变成偷抢砸建议 |
| harm-memory | 2 | 帮助之后仍记得目击的破坏，不随玩家否认改写事实 |
| unknown-thief | 2 | 发现失物但不知道是谁拿的，不把转述当目击 |
| late-return | 2 | 承认已经归还，保留逾期与先前约定 |
| instruction-data | 2 | 引文不能越权改信任或赠金币，多轮仍分清说话和事实 |
| unsupported | 1 | 不承诺生成神剑或转让村庄 |

每个场景从固定 seed42 的真实 fixture4 建立，准备工作通过现有命令执行；没有手工捏造记忆。脚本动作是测试预先指定的玩家选择，独立于模型建议。模型建议始终不自动执行；每次有效回复作为交谈记录进入同一临时世界，后续模型轮次读取这个世界的近期对话。

世界和约定 ID 使用无语义的稳定标识，评分标签、预期动作、人工评语和完整世界真相不发送给模型。模型仍只能看到 NPC4 适配器选取的猎人视角。报告可展示这些合成世界的诊断数据，不是玩家界面的全知信息入口。

## 默认离线计划

在仓库根目录、Node 24 运行：

```sh
node scripts/evaluate-npc-dialogue.mjs
# 固定输出文件名；JSON及同名HTML必须都不存在：
node scripts/evaluate-npc-dialogue.mjs --out artifacts/npc5-dialogue-eval/plan.json
```

默认不读模型配置、不创建Provider、不发网络请求。它实际建立场景、核对前置条件并审计世界重放；16轮模型响应都标“未运行”，没有语言质量通过率。计划模式不伪造模型回复，所以跨轮的模型措辞承接也未运行。

输出 JSON 与可直接离线打开的 HTML。可以展开每轮的猎人视角、记忆来源、脚本动作与自动检查，另查看人工语义问题。HTML不执行脚本、不访问外网，所有模型文本均转义；未做实际浏览器外观验收。

## 明确配置和授权后才运行真实模式

先在本项目 `.env` 配置 NPC4 的四个 `NPC_LLM_*` 字段；参见[配置说明](../../docs/runtime/NPC4-NEGOTIATION-PROVIDER.md)。CLI仅在明确live模式读取本项目 `.env`，不读取其他项目凭据。

下面是待授权后操作的命令示例，可能产生模型费用；本次没有执行外部真实调用：

```sh
# 单轮接线检查：最多1次请求。
node scripts/evaluate-npc-dialogue.mjs --mode live --case unsupported --max-requests 1 --allow-model-calls
# 讨价还价连续3轮：
node scripts/evaluate-npc-dialogue.mjs --mode live --case bargain --max-requests 3 --allow-model-calls
# 整组16轮：
node scripts/evaluate-npc-dialogue.mjs --mode live --case all --max-requests 16 --allow-model-calls
```

live必须显式指定场景、请求上限（1至32）和调用开关。缺配置、预算小于选中轮数、输出JSON或HTML已存在，都会在首个请求前拒绝。`--allow-model-calls` 是操作者的显式开关，不能替代协作者需要取得的实际授权。

请求串行、无自动重试。一个响应无效/超时，则这个场景剩余轮次标为“阻塞”，其他独立场景继续；失败请求也计入调用上限。格式有效但建议/引用不符合样例要求时，该轮标为自动失败，仍保存其说话内容供下轮继续检验。报告不会把未测轮次删掉凑出通过率。

请求上限不是金额上限。报告记录适配器调用到校验结束的墙钟耗时，以及服务商返回的 `prompt_tokens` / `completion_tokens`；缺失或不一致的usage记为unknown，绝不当成0费用。成本、定价和模型速度需要另行评估；不自动读取价格或换模型。新调用使用新的评测进程，不从既有游戏存档恢复。

## 怎样读结果

- **场景前置检查与世界重放**：确定性规则检查。对照的是真实游戏状态。
- **建议/引用检查**：检查动作类别是否属于样例允许集合，需回忆事实时是否引用指定种类的已有记忆；还验证生成零写入、保存交谈不改变资产/关系/协议。这些是可机械判定的约束。
- **人工语义复核**：模型是否说反了、误解否定、把谎话当事实、错用记忆、语气僵硬或忘记约定。自然语言不匹配固定标准句，也不以出现某个关键词作为“理解通过”。报告默认 pending/needs-human-review，不给整体语义PASS。

自动检查通过仍可能有语言问题。例如格式正确、引用存在，却把“没看见是谁”说成“我亲眼看到你偷了”；这必须人工读回复。报告列出每轮具体复核问题，尚无自动语义裁判或已签署的人工评分导入工具。

进程退出0只表示所运行的确定性检查没有失败：plan仍未调用模型，live仍待人工语义复核；退出1表示检查或调用失败，退出2表示参数/配置/输出准备被拒绝。JSON带 `completed` 区分完整结果与中断时的部分报告。每轮完成后刷新报告；异常断电仍可能损坏当时正在写入的报告，本工具不承诺崩溃恢复。

报告含场景与关键源码SHA、运行时基准提交/工作区是否有改动、模型名和端点哈希；不写密钥、Authorization、完整上游错误或日常存档。测试中使用的受控回复只属于测试夹具，**不会成为游戏中的默认NPC回答**。实时评测报告留在被Git忽略的 `artifacts/npc5-dialogue-eval`，不自动提交任何真实模型回复到公开仓库。
